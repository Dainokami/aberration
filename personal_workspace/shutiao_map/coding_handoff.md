**本任务所有写入都限定在工程内 `personal_workspace/shutiao_map/`。**

- 可以读取工程公共代码和资源，但不能修改目录外文件，包括公共脚本、插件、`project.godot`、相机配置、共享地图、设计原稿及其他协作者的修改。

- 确实需要修改公共代码或项目设置时，先完成可独立完成的工作，再说明具体文件、改动内容、原因及影响，等待用户明确同意后执行。
- 不把设置公共主场景、全局 Autoload、InputMap 或启用插件当成默认授权；可优先采用工作区内的独立入口和适配层。
- 不自动提交 Git、切换分支或覆盖用户未提交内容。

目录属于协作约定，不能阻止他人写入。独立 Git 分支可分离版本变更；同时编辑时，还需要独立工作树才能分离磁盘文件。本次不自动创建分支或工作树。

### Godot 检查也遵守边界

不得直接运行会写入工程共享 `.godot/`、导入文件或外部用户缓存的检查。先在本目录内准备隔离 Godot 项目及其缓存、日志位置，再执行测试。

隔离项目可以拥有自己的 `project.godot`。按需从公共工程读取并复制依赖，保留必要的资源路径；复制时排除 `.git/`、共享缓存和隔离项目自身，避免递归复制。记录依赖来源，避免测试了过期副本。新增隔离目录可使用本目录内的 `.gdignore` 防止共享项目扫描重复脚本。

具体隔离运行方式由 coding 对话根据本机 Godot 可执行程序与依赖确认，交付可重复执行的命令；不得以测试为由越界写入。

| `planning_markers.json` / `.csv` | 出生、成长空间、挑战与传送门候选 |

| `generation_config.json` | 本版地图生成参数快照 |

生成工具和可编辑源配置位于 `tools/generate_world_map_template.py`、`tools/world_map_template_v01.json`。保留现有交付，调整地图时输出新版本，不默认覆盖原图或原目录。

源数据目录含 `.gdignore`，不能假定其中 PNG 已成为可直接加载的 Godot 导入资源。适配器需明确采用原始数据读取，或复制到本工作区内专用运行资源位置再导入；保留源目录。

### 接入时不能误读的约定

- 默认世界为 **600×600m**，数据图 **300×300 像素**，每像素对应一个 2×2m 格子。
- 图像右为 `+X`、下为 `+Z`，世界边界为 X/Z 各 `[-300, 300)`；像素 `(u,v)` 的格中心为 `X=-300+(u+0.5)×2`、`Z=-300+(v+0.5)×2`。实现时从 metadata 读取尺寸与边界，不硬编码这些数值。
- 生态 ID 为草地 0、沙漠 1、岩石 2、水面 3；颜色以 metadata 色表为准。
- 当前灰度 0/85/170/255 分别表示实体顶面世界 Y=2/4/6/8m；陆地基准 Y=4m。相对高度 0m 不等于世界 Y=0。
- 黑色高度像素表示水底实体顶面，不表示空格；水域只按生态识别。建议水面 Y=3m 另存于 metadata，未编码在高度 PNG 中。
- 当前项目 v8 允许空气槽、高层独立放置；本模板需要连续实体柱时，应显式填充第 0..L 层，不能依赖自动补支撑。
- 模板包含 S1 出生、P1 传送门、C1–C3 挑战及 G1–G3 成长候选；**三个挑战、12m 衔接带、8m 路线净宽等仍为当前布局建议，不是不可调常量**。
- 候选框、框中心和入口接近点不等于真实预制体锚点、占用掩码或内部门坐标，必须通过资源定义进行换算。

已有检查仅证明图片编码、规划占地和部分二维路线合法；没有 PNG/JSON 到 Godot `LevelData` 的导入，也没有新地图的三维试玩。`connections.json` 中 T1–T3 尚未生成阶梯，未计入必要路线。

## 4. 正式规模与开发目标

**直接以已有 600×600m 正式地图运行开发和验收，不先制作小尺寸验证地图。** 世界尺寸仍须可配置。

每个阶段都在同一正式规模下验证。自动测试可以针对算法构造必要输入，但不能替代正式地图的完整流程、物理与性能检查。

可使用工作区内的占位关卡、怪物、奖励和 Boss 验证规则；它们仍需具有实际占地、入口、地形或交互行为。不得把漂亮预览、空框、调试文本或直接设置成功状态当作功能验收。

优先复用公共工程现有能力：

- `scripts/level/level_data.gd`：关卡源数据与分层 API。
- `scripts/level/terrain_builder.gd`：地形表现与碰撞。
- `scripts/level/level_prefab.gd`、`object_rules.gd`：预制体与物件规则。
- `scripts/runtime/level_playtest.gd`、`scripts/player_controller.gd`、`scripts/limbs/`：试玩、移动与肢体能力。

先检查这些代码的真实接口和当前规则，不按历史文档猜测 API。通过本目录内的导入器、适配层和入口场景接入，保持关卡数据与表现分离。无法只读复用的部分先说明限制，不私改公共实现。

## 5. 需要跑通的规则

### 地图与预制体

按模板建立生态和主要高度 → 选择出生并保护安全范围 → 放入 Boss 传送门区域 → 放入挑战关卡 → 填充散点小预制体 → 配置固定怪物点 → 完整检查后开局。

- 预制体和怪物按允许生态 Tag 筛选；候选池支持权重和单局数量限制。
- 挑战约 100×100m；Boss 传送门区域约 30×30m；实际占地由资源决定。
- 旋转时同步变换占地、内部地形、附件和入口。检查范围包括实际占地和衔接需求。
- 不越界、不重叠、不破坏必要路线；候选失败可有界重选，必需内容无解时报告具体原因，不强行投放或静默省略。
- 保留固定随机种子；同一模板、资源与配置版本、种子应复现同样的开局结果。
- 固定点在编辑阶段保存；自动布点只生成策划可微调的配置，不在每局任意搬动标记。

### 角色、怪物与挑战

- 玩家初始不能涉水，也不能向上跨越 2m；出生、必要成长内容和传送门之间有不依赖随机能力的路线。
- 普通怪在固定点生成，配置单批数量、存活上限、补充间隔和玩家最小生成距离；清空后等待再补充，玩家过近时延后。
- 接入现有肢体能力时通过可用接口处理；缺失的战斗或掉落能力明确标注，不擅自修改公共角色逻辑。
- 挑战目标达成后投放高级奖励，每局只完成、发奖一次；关卡内怪物由挑战控制，不混入野怪持续补充。

### 传送门、计时与胜负

- 传送门地形开局嵌入，初始未激活且不显示 Boss 入口提示。
- 到时间后给出变化与预兆，清除范围内普通怪及允许清除的小型内容，停止附近补怪，激活并揭示入口。
- 保留奖励、掉落物和挑战进度；衔接带宽度不等于清场半径。
- 主动交互进入独立 Boss 场景，不能返回大世界。
- 同一个单局计时状态跨场景保留，进入 Boss 场景不重置；时限内击败 Boss 获胜，超时仍未击败则失败。
- 总时限 `T` 和开局后激活时刻 `t` 满足 `0 < t < T`；计时从地图准备完成、玩家正式出生后开始。

可在工作区入口下保留单局管理节点，切换其世界/Boss 子场景，以避免依赖修改公共 Autoload。具体结构由实现者结合现有代码确定。

## 6. 配置与调参体验

配置集中在本目录，优先使用 Godot Resource/Inspector 或已存在的 JSON 工具，不先制作大型专用编辑器。

| 配置类别 | 需要能调整的内容 |
| --- | --- |
| 地图输入 | 模板路径、尺寸与编码检查、版本 |
| 投放 | 标记、候选池、生态、权重、数量、密度、间距与随机种子 |
| 预制体 | 资源引用、锚点、实际占地、允许旋转、入口与地形衔接 |
| 野怪 | 固定点、候选、单批数量、存活上限、补充间隔、玩家最小距离 |
| 挑战 | 目标、所属怪物组、奖励 |
| 单局 | 总时限、传送门激活时刻、预兆时长、清场范围、Boss 场景 |

第一版明确支持：**修改配置 → 校验 → 重新生成或重开本局 → 观察结果**。运行中热更新不是本轮必需项。

未定数值可以提供有明确标识的可调初值，不能伪称策划已确认。开局复制配置快照，避免正在运行的一局被后续编辑隐式改变。

提供简洁的调试入口：当前种子与阶段、剩余时间、占地与标记显示、碰撞/路线检查、重新生成、快速推进到激活前、查看补怪与挑战事件。测试用快速推进须经过正常事件逻辑，不能只改 UI 或直接跳到成功状态。

## 7. 实现顺序与阶段验收

| 阶段 | 完成内容 | 正式地图上的验收 |
| --- | --- | --- |
| 1 | 输入校验、地图导入、独立入口 | 600×600m 地形实际生成；生态、高度、水底/水面、碰撞与坐标正确；玩家能出生和移动 |
| 2 | 预制体定义、按优先级随机投放 | 真实占地、旋转、生态和入口正确；失败可定位；必要路线在嵌入后仍成立 |
| 3 | 标记配置、自动布点与微调保存 | 数量/密度生成配置，移动或删除后可保存重载；每局使用固定点 |
| 4 | 普通怪补充与挑战奖励 | 实际生成、清空、延时补充与上限生效；挑战只发一次奖励 |
| 5 | 单局计时、传送门与独立 Boss 场景 | 正常探索到激活、清场、进入 Boss、获胜或超时；时间连续且不能返回 |
| 6 | 调参和完整回归 | 修改配置并重开有效；固定种子可复现；完整单局和正式规模性能有记录 |

优先接通地图与完整流程，再逐步补齐工具体验。阶段未完成时如实说明，不因为启动成功或二维检查通过就宣称整套功能完成。

## 8. 必要验证与交付

### 自动验证

- 输入尺寸、精确编码、世界坐标、灰度高度和水域含义；非法数据明确报错。
- 实际占地与旋转、生态筛选、冲突处理、确定性及无解退出。
- 野怪清空补充、存活上限、近距离延后、清场后停止补充。
- 挑战完成与奖励幂等，受保护内容不被清场误删。
- 激活只触发一次、跨场景计时、胜负结束状态、失败后不继续刷怪或再次结算。
- 与复用范围相关的现有地形/预制体回归，在隔离项目中执行；缺失依赖或无法执行的检查单独报告，不删除失败断言。

### 三维与人工验证

正式地图中检查实际角色碰撞、初始移动限制、岸边、阶梯、关卡入口和接缝；从出生点到成长区与传送门实际走通。阶梯规划数据必须实例化后再检查，不能把规划连线当作坡道。

检查地图准备、传送门激活和场景切换前后的表现。记录生成耗时、运行帧率/帧耗时及资源占用的测试条件与实测值；若正式规模性能不足，在本目录内定位和调整，不能通过缩图替代正式验收。

无窗口脚本解析、自动逻辑测试、二维路线、离屏画面和真实窗口操作分别报告。没有完成的图形或手动检查明确列出。

### 最终交付

- 本目录内可运行的独立入口、集中配置、适配代码和测试。
- 能在正式地图上跑完整单局的启动方式、依赖准备步骤及测试命令。
- 配置说明：改哪个文件、修改后如何重开、哪些参数需重新生成地图。
- 验证结果、性能记录、已知限制及占位内容清单。
- 如存在必须修改公共工程的接入项，提供具体文件与最小改动建议，等待授权，不越界执行。
