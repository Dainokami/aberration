# 地形素材使用说明 · 程序接入测试 v0.2

交付日期：2026-10-12。目标是把四生态图片、生态交界遮罩、真实高度差和圆钝崖顶组合进引擎，做功能与画面验证。**这是一份图片和规范包；未包含 Godot 场景、材质、碰撞或已验证的引擎渲染器。**

## 1. 从哪里开始

1. 解压整个 ZIP，双击根目录 `preview.html`，无需服务器、安装依赖或联网。图片、脚本、网页必须一起保留；不要只复制 HTML。
2. 页面内同时有不规则同高交界小样、最新高度差预览、规整 47 类拓扑对照及图片画廊。高度预览默认启用“新版钝化收边”，关闭可看旧版。
3. 看完本说明，用 `spec/manifest.json` 读取文件路径、尺寸、alpha 有效范围、纹理周期、采样方式和 SHA-256。所有路径均相对包根目录。
4. 优先在独立测试场景复现“草地高 2m / 海水低 0m / 直线崖岸”，再扩展岩地、沙地、凹凸角和 4m 高差。

`reference/` 是旧版对照及效果参考；不是正式导入目录。`preview_scripts/` 为网页绘制示例，可以参考规则，不能直接当作 Godot Mesh/深度排序实现。

## 3. 世界尺寸与纹理尺度

- 世界采用 XZ 水平面、Y 高度；1 世界单位按 1m 理解。
- 逻辑地块为 **2m×2m**，高度层为 **2m**；网页用 16m×12m 的例图。2m 是编辑模数，不是每格必须独占一张顶面纹理。
- 顶面四张原图均 1254×1254：一张原图覆盖 **8m×8m**，即 4×4 格。全图实际约 156.75 px/m，属于当前图片样本尺度；正式规格的 128 px/m 不意味着本轮要预先改写图片。
- 立面三张原图均 1254×1254：一张原图覆盖 **4m×4m**。2m 侧壁取对应高度范围；4m 墙体保持相同密度，不能把同一张 2m 墙图拉长。
- 崖顶条、水线条都是 2172×724 RGBA；沿边 U 每 **8m** 一个原图周期。V 使用 alpha 有效范围，映射到横截面；不能把整张图的透明上下留白当作 0.35m 或斜面宽度。
- 灰度遮罩 256×256，对应一个 2m×2m 单元；这与连续底纹分开计算。

## 4. 同高生态交界与遮罩

底纹沿世界 XZ 连续采样，遮罩沿单格局部 UV 采样。白色表示覆盖生态，黑色表示底层生态，灰色是覆盖率。

```text
color = mix(bottom_color(world_xz), cover_color(world_xz), mask(cell_uv))
```

网页的视觉覆盖优先级为草地 > 岩石 > 沙漠 > 海水；它只决定同高混合顺序，不能用来决定谁的世界高度更高。实际高度差进入独立的侧壁/崖顶规则。

邻格编码如下，N 指 -Z，E 指 +X，S 指 +Z，W 指 -X：

| N | E | S | W | NE | SE | SW | NW |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | 2 | 4 | 8 | 16 | 32 | 64 | 128 |

相邻格属于当前覆盖生态时设位。对角位仅在对应的两个正交邻格均设位时保留；否则清除。256 个输入归一化为 47 类，读取 `blob_000.png` ～ `blob_255.png` 中存在的那 47 张。

不规则样本：`straight_blob_110_v1/v2/v3`、`outer_corner_blob_076_v1/v2/v3`、`inner_corner_blob_239_v1/v2/v3`。文件名 v1/v2/v3 对应网页 A/B/C；字母不是跨拓扑统一的强度档位。变体选取宜用格坐标与稳定种子确定，重绘时不要重新随机。

格边覆盖率沿用规整版，所以三种变体可拼接。需要其他朝向时只旋转遮罩 UV，并同步旋转邻格位值；**不要旋转世界坐标底纹**。旋转不等于增加其余拓扑：其余类仍需回退。三生态交汇、极窄条和复杂多高度交界尚需程序专门验证。

## 5. 顶面、立面和圆钝崖顶

高格比邻格高时才生成外露侧壁，低格不会反向生成另一面墙。墙体材质归高格，顶部生态与其配套立面分开使用。等高相邻格之间不画内部侧壁或崖顶。

**新版图片必须配合宽过渡面使用。** 把它仍然贴在 90° 方块的竖面上，即使放大，也不能还原本轮认可的钝化效果。

| 生态 | 顶面向内衔接 | 最大基础外悬 | 向下过渡 | 网页平面圆角半径 |
|---|---:|---:|---:|---:|
| 草地 | 0.28m | 0.24m | 0.43m | 0.58m |
| 岩地 | 0.55m | 0 | 0.42m | 0.82m |
| 沙地 | 0.65m | 0 | 0.46m | 0.88m |

这些是已认可网页样本的**视觉初值**，见 `spec/height_profiles.json`，不改变逻辑格、层高或碰撞尺寸。草皮还有约 ±0.081m 的弱轮廓起伏；实际峰值外悬可能比表内基础值略大。正式地图对单格高柱、窄台地和紧挨内外角应限制圆角/内退宽度，避免过渡带自交或把顶面吃光。

设沿边外法线为 n，逻辑边位置为 P、地形顶高为 H。横截面点为 `P + n*d(t)`，高度为 `H + dy(t)`，t 从顶面到侧壁走 0→1：

- 岩/沙采用圆滑四分之一椭圆：`d=-w+w*sin(πt/2)`，`dy=-h+h*cos(πt/2)`。它在顶面处接近水平，在壁面处接近竖直。
- 草地使用卷边控制点 `(d,dy)`：`(-0.28,0), (-0.10,0.02), (0.15,-0.025), (0.24,-0.12), (0.18,-0.27), (0,-0.43)`；插值并做足够细分。先外探，再卷回逻辑壁面。
- 平面凹凸角沿同一条圆钝轮廓转弯，再把横截面扫过去。不要在角上叠两条完整直边贴片；也不要只把顶面 mask 圆化，而立面仍留方柱尖角。
- U 沿边累计长度连续采样；V=t 对应新条的有效 alpha 范围。底层过渡面必须有不透明材质，条的透明缺口应露出草/石/沙材质，而不是看穿整个地形。
- 4m 连续墙只在真实的最高沿放一圈收边，2m 中间不重复草皮。0→2→4m 台地中的真实 2m 平台边，则可以有它自己的收边。
- 网页为了保持纵向连续，立面使用 `(x+z,-y)` 映射；轴向直墙的尺度正确，圆角处有轻微密度变化。引擎建议使用统一沿墙展开坐标与绝对高度，并处理跨层共享 UV，不能把这个网页近似当作通用 UV 展开器。

## 6. 水面与水线

水面是一个水平面，本包没有蓝色水体竖壁。连通海域采用一致水位，首轮示例为 0m；不同水位的相邻水体、瀑布、折射和水下地形不在本包内。

- 同高浅水岸：用顶面覆盖交界；若添加泡沫，铺在水位平面，不生成假崖壁。
- 低一层/两层崖岸：陆地顶面位于 2m/4m，墙体延伸到水位；崖顶跟随陆地高，泡沫沿墙脚铺在**水平水面**。
- 泡沫沿边 8m 周期，横向 0.35m；原版 alpha 范围 `[0,315,2172,412]`。原图和宽度保持原版；路径跟随调整后的崖脚。网页为防止重合闪烁上抬 0.008m，这只是预览初值，引擎应自行处理深度偏移。

## 7. 采样、alpha 与 Godot 导入建议

所有原图原样交付，不预裁切、不缩放、不改色。顶面/立面以及彩色条按颜色纹理处理；灰度 mask 按**线性数据**处理，不做 sRGB 解码。

当前手绘纹理**没有通过逐像素普通 Repeat 无缝验收**。建议顶面和立面两轴镜像采样，收边仅 U 镜像、V Clamp，遮罩两轴 Clamp。镜像能缓和对边颜色跳变，但会产生对称纹样，不能宣称已经修复为正式无缝资产。

```text
mirror(t) = 1 - abs(mod(t, 2) - 1)      // mod 返回 [0,2)
top_uv = mirror((world_xz + shared_origin) / 8)
cliff_uv = mirror((wall_distance, -world_y) / 4)
```

RGBA 条使用未预乘 alpha。`alpha_bbox_threshold_8` 是 `[x0,y0,x1,y1]`，x1/y1 为不含上界的像素边界。若使用整张原图，在 Shader 中把采样 UV 映射到这个范围；必要时按半像素内缩，避免采到上下透明留白。不能仅打开 Repeat，让 V 绕回另一条带。

Godot 最小验证建议：

1. `assets/` 导入项目独立目录；根据清单建立生态材质定义，不根据文件名猜世界尺寸。
2. 先用不透明或 unshaded 基础地表对照网页颜色。顶面/侧壁颜色纹理在自定义 Shader 中使用颜色采样约定，mask sampler 不带颜色解码。
3. 顶面与侧壁按真实 3D 生成；圆角/卷边单独处理视觉 Mesh，逻辑格与简化碰撞保留明确参数。
4. 对收边优先在同一不透明过渡材质中用 alpha 混合底色，减少透明面排序；需要实际纸片轮廓时，再测试 Alpha Scissor/Hash、双面、阴影与深度偏移。
5. Linear 过滤、mipmap、透明边界颜色扩展参数须在引擎实际测试。尤其检查远距离细线、黑边、Alpha Scissor 缺口和镜像折返点的 mip 亮线。包中没有强制 `.import` 配置。
6. 页面角度是观察候选值，不要自动覆盖项目 `data/art_profile.tres`。网页默认俯角 40°、水平角 32°，可在 25°～60° / 20°～65° 中比较；最终相机由项目确认。

## 8. 建议的第一轮引擎验收

| 测试 | 观察点 |
|---|---|
| 草/沙、草/岩、岩/沙及三种陆地/水的同高交界 | 世界底纹跨格连续；mask 方向正确；内外角无缺口；稳定变体不跳 |
| 三段直边 A/B/C 混合 | 格边无颜色缝；边缘细节过滤后仍连接 |
| 草、岩、沙各 2m 与 4m 直崖 | 顶面到立面转折够钝；侧壁密度一致；4m 中部无多余 cap |
| 凸角、凹角、单格柱与 1 格窄台地 | 角上无两条贴片重叠；过渡带不自交；视觉内退不吃掉玩法区域 |
| 0→2→4m 连续台地 | 所有转角补片闭合；层间侧壁/UV 连续；低处不能透视穿洞 |
| 2m/4m 陆地对 0m 海水 | cap 在陆顶，泡沫在水位；没有水体竖墙或悬空泡沫 |
| 确认相机 + 候选偏角，远近两档 | 纹理密度、条带接角、透明排序、mipmap 接缝 |
| 显示碰撞与逻辑格，角色靠近崖沿 | 视觉悬出/内退与可走范围的关系明确 |

请把未通过项连同截图、相机参数、材质过滤方式和对应图片 ID 反馈。优先反馈顶/侧衔接、层间洞、凹角排序、纸条感与碰撞范围，而不只评价单张图好不好看。

## 9. 已验证与边界

所有 PNG 原样复制并记录 SHA-256；离线网页资源路径、控件逻辑与部分实际 Canvas 输出做了检查。规整 47 类与不规则小样有连接约定检查；使用了内置 ImageGen 生成彩色纹理/新版条，代码生成灰度拓扑数据。

程序仍须验证真实 3D 深度、透明排序、几何闭合、碰撞与项目相机。网页为小规模观察模型，包含视觉近似和逐三角形绘制，不适合照搬为大世界实时渲染器；也没有通过工具浏览器 GUI 或 Godot 集成验收。不要从网页看起来正常推断引擎已经通过。

完整原始尺寸、透明范围、提示词、交付文件哈希、视觉横截面节点均随包提供。需要重新量产严格无缝纹理、补齐不规则 47 类或建立正式转角 Mesh 时，应另做下一轮资源制作。
